Metrics
=======

This lab has two modules, based on a Wireshark trace ("trace.pcapng",
in this directory) that was automatically generated for you when
this lab started: it contains a real file download (over plain HTTP)
for the Throughput module, and real ping traffic for the Latency
module. Two reference files are also provided: "wget_output.txt" and
"ping_output.txt" -- the real, unmodified terminal output of the wget
and ping commands used to generate your trace.

Write your answers in answer.txt, one per line, in the exact format
shown in that file. Do not change the question numbers.

Because your trace is unique to you, your numeric answers will not
match anyone else's -- that's expected. The grader recomputes the
correct answers directly from YOUR trace file.

-----------------------------------------------------------------
Module 1: Throughput
-----------------------------------------------------------------

The below questions are based on "trace.pcapng". The output of wget
is given in "wget_output.txt".

Q1. What is the exact size of the downloaded file in bytes?
    Format X (e.g. 12895347).

Q2. Using the trace, how can you determine the downloaded file size?
    Select all that apply, comma-separated.
      A. From the TCP SYN packet corresponding to the very 1st
         packet
      B. From the GET request
      C. From the HTTP OK response
      D. From a TCP ACK packet
    Hint: TCP as such does not deal with application level details.
    When you request a file via GET, you don't normally know its
    size -- this info is in the server's response, in the HTTP OK
    packet, under "Content Length".

Q3. What is the percentage overhead involved in downloading the
    file? Suppose X extra bytes had to be exchanged to download a
    file of size Y; overhead is X*100/Y %. Format X.x (e.g. 12.4).
    Hint: filter to just this download's TCP stream. Look under
    statistics -> protocol hierarchy, or sum up frame lengths for
    that stream, for the total bytes exchanged on the wire.

Q4. How much time did it take to download the file, in seconds? This
    is computed from the time the request was initiated, to the time
    the file was fully received. Format X.yz (e.g. 10.41).

Q5. What is the throughput achieved by this connection? Measure time
    as in Q4. Express it in Kilobytes per sec (kilo = 1000, not
    1024). Format X.y (e.g. 289).
    Hint: throughput = bytes / time, converted to KB/s.

Q6. [Written answer] Now look at wget_output.txt. How does what you
    measured through the trace match with what wget printed?
    Note: this question is graded manually, not by the autograder.

Module 2: Latency
-----------------------------------------------------------------

The below questions are based on "trace.pcapng", which also contains
ping traffic. The output of ping is given in "ping_output.txt".

Q7.  What is the size of the ICMP payload in bytes -- i.e. the data
     generated by the ICMP module, encapsulated by the layer below?
     Do not include any Ethernet/IP headers. Format X (e.g. 12).
     Hint: click the first ICMP packet, then ICMP in the packet
     details pane, then look at the status bar at the bottom.

Q8.  What time interval did ping use to send "request" packets?
     Express it in seconds. Format X (e.g. 10).

Q9.  In the trace, identify the FIRST request and determine the RTT
     corresponding to it. Express it in microseconds. Format X (e.g.
     230).

Q10. In the trace, identify the SECOND request and determine the RTT
     corresponding to it. Express it in microseconds. Format X (e.g.
     230).

Q11. [Written answer] Look at ping_output.txt. How does what you
     measured through the trace match with what ping printed?
     Note: this question is graded manually, not by the autograder.
